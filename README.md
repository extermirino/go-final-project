# Планировщик задач

## Описание проекта

Планировщик задач позволяет создавать, редактировать, удалять и выполнять задачи.
Также есть возможность задать необходимую периодичность повторения задачи при её создании или редактировании.
Для задачи можно указать дату, на которую она будет назначена, название, а также комментарий.

## Список выполненных заданий со звёздочкой

1.  Настройка порта: Реализована возможность определять порт извне,если задана переменная окружения `TODO_PORT`
2.  Настройка БД: Реализована возможность определять путь к файлу базы данных, если задана переменная окружения `TODO_DBFILE`
3.  Правила повторения: Реализован алгоритм вычисления дат для `еженедельного` и `ежемесячного` повторения задач
4.  Поиск: Добавлена фильтрация задач по подстроке в заголовке/комментарии, а также выборка задач на конкретную дату через `строку поиска`
5.  Аутентификация: При установке пароля в переменной окружения`TODO_PASSWORD`, доступ к API становится защищен с помощью JWT-токенов.
6.  Контейнеризация: Создан `Docker-образ` для удобного развертывания

## Запуск кода локально

1. Перед запуском, при необходимости, в терминале можно задать переменные окружения. 
В нашем случае мы установим переменную для пароля с помощью команды `export TODO_PASSWORD=12345`.
Остальные переменные можно также задать с помощью команды `export` или оставить дефолтными: 
путь к БД - scheduler.db, порт - 7540
2. Запустить приложение через терминал, с помощью команды `go run .` или `go run main.go`

## Инструкция по запуску тестов

В директории `tests` находятся тесты для проверки API, которое должно быть реализовано в веб-сервере.
Перед запуском тестов, в файле `tests/settings.go` проверьте следующие переменные:
1. Значения переменных `Port` и `DBFile` не важны, т.к. мы реализовали возможность настройки порта и БД через
переменные окружения, так что оставим их дефолтными: `7540` и `"../scheduler.db"` соответственно
2. Значение переменных `FullNextDate` и `Search` должны быть равны `true`, т.к. мы реализовали алгоритм 
вычисления дат для `еженедельного` и `ежемесячного` повторения задач, а также поиск задач по тексту / дате
3. Если значение переменной окружения `TODO_PASSWORD` отличается от `12345`, корректное значение для переменной `Token`
можно получить выполнив следующие действия:

1)Запустите сервер через терминал, выполнив команду `go run .`

2)Получите значение для переменной `Token` через терминал, выполнив команду ниже:
`
curl -X POST http://localhost:7540/api/signin \
-H "Content-Type: application/json" \
-d '{"password":"<ВАШ ПАРОЛЬ>"}'
`

Обратите внимание, что вместо <ВАШ ПАРОЛЬ> нужно подставить тот пароль, который был задан 
в переменной окружения `TODO_PASSWORD`.

Например :`-d '{"password":"12345"}'`

4. В терминале выполните команду `go test ./tests`

## Инструкция по сборке и запуску проекта через Docker

Проект использует двухэтапную сборку на базе `golang:1.25` и `ubuntu:latest`.
Для сохранения данных используется монтирование базы данных с хост-машины.

Сборка образа осуществляется через терминал, с помощью команды `docker build -t todo-service .`
Запустить контейнер можно через терминал, выполнив команду ниже:
`
docker run -p 7540:7540 \
-v $(pwd)/scheduler.db:/app/scheduler.db \
-e TODO_PASSWORD=12345 \
--name todo-app \
todo-service
`.

Для того, чтобы остановить работу контейнера, достаточно нажать комбинацию клавиш `Ctrl+C`.

При необходимости, в команду выше в самое начало можно добавить `-d`, если нужно запускать контейнер в фоне.
В таком случае, для остановки контейнера, в терминале можно выполнить команду `docker stop todo-app`, а
для повторного запуска контейнера - команду `docker start todo-app`.
